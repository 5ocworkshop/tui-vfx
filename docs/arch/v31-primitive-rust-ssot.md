# V3.1 Primitive Rust SSOT

## Status

Production-ready architecture direction after peer review. This document covers **primitive catalog instance ownership** for the clean-sheet `tui-vfx-compost` v3.1 runtime.

It does **not** change the v3.1 contract-schema ownership model. The schema layer remains owned by Rust DTOs in `tui-vfx-contract`, with checked JSON Schema fixtures under `schemas/v3.1/contract/` generated by the existing `UPDATE_SCHEMAS=1 cargo test -p tui-vfx-contract --test test_schema_generation -- checked_in_contract_schemas_are_current` path unless/until that flow is moved behind an `xtask schemas` command.

The accepted taxonomy is:

| Layer | Source of truth | Generated artifact | Current generator reality |
| --- | --- | --- | --- |
| **Contract schema** | `tui-vfx-contract` Rust DTOs and rustdoc | `schemas/v3.1/contract/*.schema.json` | Contract test with `UPDATE_SCHEMAS=1`; no `xtask schemas` command yet |
| **Primitive catalog instance** | Accepted Rust primitive/source declarations in `tui-vfx-compost`, plus temporary bootstrap carry-forward for unported descriptors | `descriptors/v3.1/packs/primitive.json` | Target state requires new `cargo xtask descriptors gen/check`; command does not exist today |

When this document says “Rust SSOT,” it means the **primitive catalog instance layer** only. The v3.1 contract schema remains the hard boundary and validation authority.

## Problem

`descriptors/v3.1/packs/primitive.json` currently acts as a shared descriptor pack for recipes, validators, player tooling, and tests. It declares source descriptors and effect descriptors: ids, versions, display names, domains, cell access, scope support, write support, lifecycle metadata, inputs, and outputs.

Today it must be treated as a **migration seed**, not semantic truth. It was assembled before the clean `tui-vfx-compost` primitive runtime exists, and drift has already been observed between descriptor entries, authoring aliases, canonicalized recipes, and legacy implementation semantics. Examples from prior corpus/load work include incorrect input kinds, copied legacy debug-field descriptions, descriptor names that only line up through alias mappings, and capability metadata with no compile-time or runtime connection to implementation behavior.

The structural failure is that the primitive's facts are currently spread across several places:

- provisional `primitive.json` descriptor entries;
- v3.1 contract DTOs and generated JSON Schemas;
- authoring alias `paramMapping` tables;
- canonicalization behavior;
- legacy `tui-vfx-compositor` filters/masks/sampler implementations;
- `tui-vfx-style` / `tui-vfx-content` behavior for non-compositor effects;
- corpus shorthand and canonical fixtures;
- current `tui-vfx-compost` validation/render seams.

The clean-sheet v3.1 runtime needs one accepted edit point per primitive, a mechanical generated descriptor artifact, and a lock that prevents descriptor/runtime drift from reappearing.

## Goal

For every accepted v3.1 primitive/source, a Rust declaration under `crates/tui-vfx-compost/src/` owns the primitive catalog instance facts. The low-churn implementation path is to use the existing compost axis directories (`filters/`, `masks/`, `samplers/`, `shaders/`, `styles/`, `content/`, `source/`) unless Phase 0 deliberately introduces a `primitives/` umbrella module:

- id, version, display name, category;
- domain/kind;
- descriptor capabilities (`cellAccess`, `scopeSupport`, `writeSupport`, lifecycle);
- typed inputs with defaults, ranges, allowed enum values, optionality, bindability, runtime mutability, units, and semantic hints;
- typed outputs when the runtime substrate supports effect-output capture;
- runtime implementation for the appropriate domain, or descriptor-only registration with structured `EffectNotImplemented` / `RuntimeNotImplemented` behavior.

`descriptors/v3.1/packs/primitive.json` becomes a generated artifact emitted from the registry. During migration, unported descriptors live in `descriptors/v3.1/packs/primitive.bootstrap.json` and are carried forward into the generated unified pack. Each port removes one descriptor from the bootstrap file and replaces it with a Rust-derived entry. The bootstrap file is the burndown ledger. When it is empty, the primitive catalog instance is fully Rust-derived.

The runtime path and the codegen path consume the same registry:

- `tui-vfx-compost` runtime uses the in-process registry for descriptor validation and runtime dispatch;
- external tools that do not link the substrate consume generated `primitive.json`;
- CI round-trip lock catches drift and directs maintainers back to Rust/bootstrap sources, never to hand-edit `primitive.json`.

## Non-goals

- This document does not redesign the v3.1 contract schema DTOs.
- This document does not require all primitives to have runtime implementations before descriptor coverage reaches 100%.
- This document does not bless current `primitive.json` values as correct; they are provisional migration inputs.
- This document does not keep legacy runtime traits (`Filter`, `Mask`, `Sampler`) as implementation dependencies. Legacy files are semantic references only.
- This document does not require effect-output capture in Phase 1/2. Outputs remain a placeholder until substrate support exists.

Load-bearing properties:

1. **Contract shape and catalog content are separate layers.** `tui-vfx-contract` owns valid shapes; `tui-vfx-compost` owns accepted primitive catalog instance content.
2. **The runtime path and codegen path read the same registry.** A descriptor cannot validate one way for runtime and another way for generated tools.
3. **Bootstrap is temporary and visible.** Carry-forward descriptors preserve external behavior during migration while creating a concrete burndown ledger.
4. **The generated artifact is downstream.** `primitive.json` is never the edit point after this plan starts; hand edits fail the round-trip lock.

## Per-primitive truth hierarchy

When porting a primitive, do not treat any single current artifact as complete truth. Resolve conflicts in this order:

1. **Contract schema:** v3.1 DTO/schema shape determines legal descriptor/value/source forms.
2. **Alias/canonicalize behavior:** authoring `paramMapping` and canonicalization determine field names and authoring compatibility expectations.
3. **Legacy semantics where present:** `tui-vfx-compositor`, `tui-vfx-style`, `tui-vfx-content`, or `tui-vfx-shadow` implementation files describe behavior but are not imported by new primitive files.
4. **Corpus evidence:** shorthand/canonical fixtures show real migrated usage and edge cases.
5. **Authorial decision:** v3.1-only effects or ambiguous mappings require documented disposition.

If these conflict, the port must record the decision in code comments/tests/docs rather than silently picking one.

## Descriptor and runtime model

### Descriptor trait

Every effect primitive implements one descriptor trait. It is static, serializable, and runtime-domain agnostic.

```rust
pub trait EffectPrimitive {
    const ID: &'static str;
    const VERSION: &'static str;
    const DISPLAY_NAME: &'static str;
    const CATEGORY: Option<&'static str>;
    const DOMAIN: EffectDomain;
    const CELL_ACCESS: CellAccess;
    const SCOPE_SUPPORT: ScopeSupport;
    const WRITE_SUPPORT: WriteSupport;
    const LIFECYCLE: EffectLifecycle;

    type Inputs: PrimitiveInputs;
    type Outputs: PrimitiveOutputs = NoOutputs;

    fn input_specs() -> BTreeMap<EffectInputId, EffectInputSpec>;
    fn output_specs() -> BTreeMap<EffectOutputId, EffectOutputSpec> {
        BTreeMap::new()
    }
}
```

`PrimitiveOutputs` exists as a placeholder. Phase 1/2 support only `NoOutputs`; effect-output capture is explicitly deferred.

### Domain-specific runtime traits

The single `EffectRuntime::apply(inputs, CellView, EffectCtx)` shape is rejected because it only fits cell-mutating filters/shaders. Runtime behavior is domain-specific. Exact argument names and helper types are pinned in Phase 0, but the architectural shape is:

```rust
pub trait CellShaderRuntime: EffectPrimitive {
    fn apply_shader(
        inputs: &Self::Inputs,
        cell: &mut CellView<'_, Self>,
        ctx: &EffectCtx<'_>,
    );
}

pub trait FrameFilterRuntime: EffectPrimitive {
    fn apply_filter(
        inputs: &Self::Inputs,
        cell: &mut CellView<'_, Self>,
        ctx: &EffectCtx<'_>,
    );
}

pub trait MaskRuntime: EffectPrimitive {
    fn test_mask(
        inputs: &Self::Inputs,
        ctx: &EffectCtx<'_>,
    ) -> Visibility;
}

pub trait CoordinateSamplerRuntime: EffectPrimitive {
    fn sample(
        inputs: &Self::Inputs,
        ctx: &EffectCtx<'_>,
    ) -> SamplerOutput;
}

pub trait ContentTransformRuntime: EffectPrimitive {
    fn transform(
        inputs: &Self::Inputs,
        surface: &mut SurfaceView<'_>,
        ctx: &EffectCtx<'_>,
    ) -> TransformOutcome;
}
```

Source descriptors are not effects and have their own descriptor/runtime pair:

```rust
pub trait SourcePrimitive {
    const ID: &'static str;
    const VERSION: &'static str;
    const DISPLAY_NAME: &'static str;
    const CATEGORY: Option<&'static str>;
    const KIND: SourceKind;
    const LIFECYCLE: SourceLifecycle;

    type Inputs: PrimitiveInputs;

    fn input_specs() -> BTreeMap<SourceInputId, SourceInputSpec>;
    fn output_spec() -> SourceOutputSpec;
    fn asset_specs() -> BTreeMap<AssetId, AssetRequirement>;
}

pub trait SourceRuntime: SourcePrimitive {
    fn materialize(inputs: &Self::Inputs, ctx: &SourceCtx<'_>) -> Result<Surface, SourceError>;
}
```

The descriptor registry is shared, but runtime dispatch is not forced through one universal ABI.

### Cell view and context

`CellView<'_, P>` is the typed cell handle the substrate gives cell shader and frame-filter runtimes. It exposes v3.1 cell channels: glyph, foreground, background, modifiers, modifierAlpha, and role. Phase 0 must decide whether channel access is enforced:

- at compile time through const-generic/type-state gates; or
- through runtime debug assertions plus tests.

Compile-time enforcement is preferred for type safety, but it may increase substrate complexity. Runtime enforcement is acceptable only if the test and CI gates are strong enough to catch channel misuse before release.

`EffectCtx<'_>` is the per-sample/per-cell context bundle. It should be the only runtime state lookup handle primitives use. It carries, or delegates to sub-handles for:

- scope iteration metadata;
- sampled-source coordinates;
- destination coordinates;
- dimensions;
- role/scope evaluation input;
- graph parameters;
- graph signals;
- graph values;
- lifecycle phase progress;
- clocks and absolute sample time.

### Scalar and input wrappers

Phase 0 must choose the home for typed v3.1 scalar wrappers. Options:

1. extend `tui-vfx-contract`;
2. create a new `tui-vfx-types-v31` crate;
3. extend `tui-vfx-types`.

The preferred direction is `tui-vfx-contract` for descriptor/value semantics that are part of the v3.1 contract, with low-level cell/color/role types continuing to live in `tui-vfx-types` where they already exist. The risk is coupling the contract crate to runtime resolution traits; the implementation should keep runtime-only traits in `tui-vfx-compost` if that coupling becomes visible.

Input wrappers express descriptor bindability only:

```rust
pub struct Literal<T: PrimitiveScalar>(T);
pub struct Bindable<T: PrimitiveScalar>(BindableInput<T>);

pub enum BindableInput<T> {
    Resolved(T),
    Bound(ValueSource),
}
```

Wrapper choice determines descriptor `bindable: false|true`; it does not determine runtime resolution cadence.

### Scheduling policy for bindable inputs

Resolution cadence is driven by `ValueSource` kind, runtime mutability, and graph topology. The scheduler must not infer cadence solely from `Bindable<T>`.

| `ValueSource` kind | Default resolution cadence | Notes |
| --- | --- | --- |
| `literal` | load time or primitive instantiation | Equivalent to `Literal<T>` after validation. |
| `parameter` | element/sample cache unless host mutability says otherwise | Use default/fallback at load/sample time. |
| `signal` | phase start or runtime sample depending on signal declaration | Must respect `RuntimeMutability::PhaseStart` vs `Runtime`. |
| `map` | same cadence as nested `from`, with cheap transform | Numeric validation at load where possible. |
| `phaseProgress` | per sample, not per cell unless cell context changes it | Lifecycle phase comes from `SampleContext`. |
| `clock` | per frame/sample | Current clock vocabulary is recipe/phase/loop seconds. |
| `sampledField` | per cell | Coordinates may vary per destination/sample cell. |
| `signalExpression` | per sample unless expression references cell fields later | Current compost evaluates expression from loop time. |
| `graphValue` | topology-dependent: per node, per frame, or per cell | Must respect producer output shape once effect-output capture exists. |

Use the actual `RuntimeMutability` vocabulary from `tui-vfx-contract`: `compileTime`, `phaseStart`, `resetOnly`, `runtime`.

## Codegen and round-trip lock

Add a new `xtask` command family:

```bash
cargo xtask descriptors gen
cargo xtask descriptors check
```

`gen`:

1. constructs `EffectRegistry`;
2. installs Rust-derived effect/source descriptors and runtimes;
3. reads `descriptors/v3.1/packs/primitive.bootstrap.json`;
4. installs bootstrap carry-forward descriptors for ids not yet Rust-derived;
5. emits unified `descriptors/v3.1/packs/primitive.json` with deterministic ordering;
6. validates the emitted pack against `schemas/v3.1/contract/descriptor-pack.schema.json`;
7. writes the output.

`check` does the same generation in memory and fails if checked `primitive.json` differs.

Round-trip lock:

```rust
#[test]
fn primitive_pack_matches_registry_truth() {
    let registry = build_registry_with_bootstrap();
    let emitted = generate_primitive_pack_json(&registry);
    let on_disk = std::fs::read_to_string("../../descriptors/v3.1/packs/primitive.json").unwrap();

    assert_json_eq_or_diff(
        emitted,
        on_disk,
        "primitive.json out of date — edit Rust/bootstrap source and run `cargo xtask descriptors gen`",
    );
}
```

Compare parsed JSON or canonicalized pretty JSON, not raw bytes, to avoid churn from formatting-only differences.

## Bootstrap carry-forward rules

`primitive.bootstrap.json` is temporary and strict:

- It contains only descriptor entries not yet represented by Rust declarations.
- It is validated before registry installation.
- It is never consumed by external tools directly; external tools consume unified `primitive.json`.
- It must monotonically shrink during Phase 3 except when a deliberate revert is documented.
- A Rust-derived descriptor wins over bootstrap if both contain the same id; CI should reject duplicate ids to force cleanup.
- Completion is bootstrap empty plus round-trip green.

This solves the Phase 1 problem where a one-effect generated pack would otherwise break existing tests and external tools.

## Macro: `#[derive(PrimitiveInputs)]`

Phase 1 should hand-author specs for the first three primitives to crystallize patterns across three runtime domains. Phase 2 adds the derive.

The derive generates:

1. `fn specs() -> BTreeMap<EffectInputId, EffectInputSpec>` or source equivalent;
2. `impl PrimitiveInputs for FooInputs`;
3. `impl Default for FooInputs` when defaults are complete;
4. compile-time rejection of unknown wrapper types.

Field attributes:

- `default = <expr>` — required unless optional;
- `range = <range>` — numeric range;
- `description = "..."`;
- `unit = "..."`;
- `semantic = "..."`;
- `runtime_mutability = <RuntimeMutability>` — exact values map to `compileTime`, `phaseStart`, `resetOnly`, `runtime`;
- optional schema hints for structured payloads.

Enum allowed values should use a small `PrimitiveEnum` trait/derive in Phase 2. Do not block Phase 1 on enum reflection; hand-author enum specs for the first ports.

| `tui-vfx-style`, `tui-vfx-content`, `tui-vfx-shadow` | Forbidden for new primitive ports. Existing compost usage is grandfathered temporarily and should be retired by Phase 0/0.5 cleanup tickets. |
| `tui-vfx-types` | Allowed for low-level shared cell/color/role/scalar primitives already owned outside legacy runtime. |
| `tui-vfx-contract` | Allowed and expected for v3.1 contract DTOs and descriptor vocabulary. |

Add `test_no_legacy_imports.rs` to enforce the permanent and new-port rules for the compost axis directories and `src/source/`, with temporary allowlist entries only for grandfathered non-port code scheduled for Phase 0/0.5 cleanup.

## Constraints

- No hand edits to generated `primitive.json` except during bootstrap initialization; after generator lands, edits must go to Rust primitive/source files or `primitive.bootstrap.json`.
- No single universal runtime ABI that hides domain differences.
- No partial runtime ports. A descriptor can be descriptor-only, but a registered runtime must be complete enough for deterministic tests.
- No `inventory` / `linkme` registration in the initial implementation.
- No new primitive imports from legacy runtime crates.
- No derive macro before `filter.dim`, `mask.dissolve`, and `sampler.gravity` prove the substrate across at least three domains.
