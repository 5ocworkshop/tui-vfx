# v3.1 Contract / Engine Boundary

## Status

Phase D3 defines a **logical boundary** inside `tui-vfx-next`. It does not split crates and it does not implement descriptors, recipes, template expansion, runtime bindings, studio manifests, phase graphs, legacy migration, or real effect ports.

The goal is to make future descriptor work safe by answering one question first:

```text
Which names are stable v3.1 contract vocabulary, and which names only exist to prove the clean-room engine semantics?
```

## Boundary rule

```text
Contract vocabulary
    stable semantic words future descriptors and canonical recipes may reference

Proof implementation
    small execution harness that proves contract behavior in tests

Schema roots
    checked machine-readable artifacts under schemas/v3.1/next

Test-only scaffolding
    helpers that exist only inside tests and must not become public contract
```

A type can be contract vocabulary without being a schema root. A proof artifact can be public for tests and experiments without being the future descriptor model.

## Public contract vocabulary

These names are the current stable v3.1 vocabulary that future descriptors and canonical recipe schemas may reuse.

### Surface and cell channel vocabulary

- `Surface`
- `SurfaceMetadata`
- `CellChannel`

A surface remains dense, rectangular, grid-first, and composed of visual cells plus one semantic role channel per cell.

### Scope vocabulary

- `ScopeSpec`
- `CoordinateSpace`
- `RoleSpace`

`ScopeSpec` is the current canonical generalized scope vocabulary. It remains deliberately small: `All`, `Role`, `Rect`, `RowRange`, and `ColumnRange`.

Coordinate and role spaces remain **operation-level context**, not fields inside `ScopeSpec`, for D3. That keeps one reusable scope value from baking in one execution context. Future descriptor work should declare the operation's coordinate and role-space defaults or overrides alongside the scope it references.

Current defaults stay locked:

- geometry scopes default to `CoordinateSpace::DestinationLocal`
- role scopes default to `RoleSpace::SampledSource`

### Write vocabulary

- `CellWrite`
- `CellWritePolicy`
- `RoleWritePolicy`

Pipeline execution and scene composition reuse this same write vocabulary.

The shared rule remains:

```text
SkipTransparentEmpty skips and preserves current destination cell + role.
WriteCell writes the cell exactly, including empty transparent cells.
```

Role writes remain explicit:

- preserve destination role
- copy sampled-source role
- set an explicit role

### Sampler vocabulary

- `CoordinateSampler`
- `PipelineSampler`
- `ShiftSampler`

`CoordinateSampler` is the behavioral sampler contract. `ShiftSampler` is stable proof vocabulary for non-identity sampled-source semantics.

`PipelineSampler` remains a checked schema root for the Phase C proof pipeline. Its name is intentionally pipeline-shaped. A later descriptor phase may rename or wrap sampler declarations for generalized descriptors, but it should preserve the same sampled-source semantics.

### Diagnostics vocabulary

- `SurfaceDiagnostic`
- `SurfaceDiagnosticCode`
- `DiagnosticLevel`

Diagnostics use stable codes plus optional path strings. D3 keeps path strings as the current convention and defers structured fields such as `elementId` or `stageName` until descriptor/recipe schemas create the surrounding identity model.

Current path conventions:

- pipeline stage diagnostics use `pipeline.stage[index].name`
- scene element diagnostics use `scene.element[index].id`

### Scene and element vocabulary

- `Scene`
- `SceneElement`
- `SceneOutcome`
- `ElementId`
- `LayerId`
- `ElementPlacement`
- `ClipPolicy`

Scene composition stays minimal: element identity, optional layer grouping, signed placement, z/declaration order, clipping policy, and the shared cell/role write policies.

### Outcome vocabulary

- `ApplyOutcome`
- `PipelineOutcome`
- `SceneOutcome`

Outcomes are public result vocabulary. They report final surfaces, counts, and diagnostics. They are not a runtime event system.

### Domain vocabulary

- `EffectDomain`

`EffectDomain` is a small vocabulary seed for future descriptors. It does not mean the descriptor model exists yet.

## Proof implementation and proof-only public artifacts

These names exist to prove semantics, not to define the future descriptor or recipe implementation shape.

### Engine proof harness

- `SurfaceEngine`
- `fnc_apply_from_source_with_sampler::apply_from_source_with_sampler`
- `fnc_scope_coordinate::scope_coordinate`

These are execution helpers. Future schemas should not expose their function shapes.

### Pipeline proof harness

- `SurfacePipeline`
- `PipelineStage`
- `PipelineOutcome`
- diagnostic annotation helpers

`SurfacePipeline` is a public checked schema root **for the current clean-room proof pipeline**. It is not the final runtime graph, phase graph, node graph, recipe compiler, or descriptor registry.

`PipelineStage` is a toy proof enum. Its variants prove ordering, sampling, visual-preserve-role behavior, explicit role writes, and scoped glyph rewrite behavior. Future descriptor work must not treat `PipelineStage` as the effect descriptor model.

### Effect proof artifacts

- `DimEffect`
- `ExplicitRoleWriteEffect`
- `EffectDescriptor`

These are small proof artifacts. `EffectDescriptor` remains deliberately outside checked schema roots. The real descriptor model starts in Phase E.

### Evaluation plumbing

- `ScopeEvalInput`
- `IdentitySampler`

These are public because tests and proof helpers use them. They are proof/evaluation plumbing, not descriptor-facing contract vocabulary and not separate schema roots in D3.

## Test-only scaffolding

Test helpers in `crates/tui-vfx-next/tests/test_surface_contract.rs`, `test_scene_contract.rs`, `test_schema_generation.rs`, and `test_contract_boundary.rs` are not contract vocabulary. They may create cells, surfaces, scene elements, and schemas to prove behavior, but they must not be referenced by future public docs as implementation APIs.

## Current checked schema roots

Checked schemas live in `schemas/v3.1/next/`:

| Schema | Rust root | D3 classification |
|---|---|---|
| `surface.schema.json` | `Surface` | contract root |
| `scope.schema.json` | `ScopeSpec` | contract root |
| `write.schema.json` | `CellWrite` | contract root |
| `sampler.schema.json` | `PipelineSampler` | proof pipeline sampler root |
| `pipeline.schema.json` | `SurfacePipeline` | proof pipeline root |
| `diagnostic.schema.json` | `SurfaceDiagnostic` | contract root |
| `scene.schema.json` | `Scene` | contract root |
| `element.schema.json` | `SceneElement` | contract root |
| `outcome.schema.json` | `SceneOutcome` | contract root |

D3 does not add schema roots. Existing schema roots remain current.

## Decisions locked by D3

```text
SurfacePipeline:
    checked proof-pipeline schema root, not final runtime graph

PipelineStage:
    toy proof enum, not future effect descriptor model

ScopeSpec:
    canonical generalized scope vocabulary for now

CoordinateSpace / RoleSpace:
    operation-level defaults/overrides, not fields inside ScopeSpec

Pipeline and scene write behavior:
    reuse CellWritePolicy and RoleWritePolicy

Diagnostics:
    keep stable codes and path strings now; defer structured identity fields

Crate shape:
    keep tui-vfx-next as one crate; use logical modules before physical split
```

## Logical modules in code

`crates/tui-vfx-next/src/lib.rs` exposes three Phase D3 grouping modules:

- `contract` — stable v3.1 vocabulary exports
- `proof` — clean-room proof harness and toy implementation exports
- `schema_roots` — checked schema root exports

The existing top-level exports remain for compatibility with prior phase tests. The grouping modules are documentation and import guidance, not a breaking API change.

## Non-goals

D3 deliberately does not implement:

- effect descriptor expansion
- recipe schema/compiler
- source authoring schemas
- template expansion
- runtime bindings
- phase graph
- trigger engine
- studio manifest
- legacy migration
- real effect ports
- full layer graph
- complex blend modes

## Handoff to Phase E

Phase E can start the effect descriptor model with this boundary in place. Descriptors should reference the contract vocabulary above and should not inherit toy pipeline stage shapes.
