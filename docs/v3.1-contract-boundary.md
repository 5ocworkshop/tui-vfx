# v3.1 Contract / Engine Boundary

## Status

Phase D3 defined a **logical boundary** inside `tui-vfx-next`. Phase E0 makes that boundary physical by moving stable DTOs into `tui-vfx-contract`. Phase E1 adds the first durable `EffectDescriptor` contract root to `tui-vfx-contract`. Phase F1 adds typed value/input specifications to descriptors. Phase F2 adds declarative value sources, public parameters, host signals, and bindable parameter-target bindings. Phase G1 adds the canonical graph container, stable graph/node identity, descriptor-backed nodes, deterministic node order, and graph-level validation. Phase G2 proves that canonical graph can drive ordered toy execution in `tui-vfx-next`. Phase G3 adds stable `GraphStep` topology and `ParallelMergePolicy`, with proof-only channel deltas for parallel merge execution. Phase G4 adds graph-local node output/value-bus DTOs, descriptor output declarations, `ValueSource::GraphValue`, `GraphValueShape`, and `GraphValueMergePolicy`, with proof-only value-bus execution. Phase H0 adds stable source and asset DTOs for surface producers, source instances, typed source inputs, structural asset refs, source output roles/size behavior, and validation. These phases still do not implement production runtime execution, runtime stores, F2 binding execution, direct node/effect-input binding targets, canonical recipe documents, template expansion, source-local pipeline syntax, studio manifests, phase graphs, real asset loading, real procedural rendering, legacy migration, or real effect/source ports.

The goal is to make future descriptor work safe by answering one question first:

```text
Which names are stable v3.1 contract vocabulary, and which names only exist to prove the clean-room engine semantics?
```

## Boundary rule

```text
Contract vocabulary
    stable semantic words future descriptors and canonical recipes may reference

Proof implementation
    small execution harness that proves contract behavior in tests

Schema roots
    stable contract artifacts under schemas/v3.1/contract
    proof-pipeline artifacts under schemas/v3.1/next

Test-only scaffolding
    helpers that exist only inside tests and must not become public contract
```

A type can be contract vocabulary without being a schema root. A proof artifact can be public for tests and experiments without being the future descriptor model. Stable contract vocabulary now lives in `tui-vfx-contract`; proof artifacts remain in `tui-vfx-next`.

## Public contract vocabulary

These names are the current stable v3.1 vocabulary that future descriptors and canonical recipe schemas may reuse.

### Surface and cell channel vocabulary

- `Surface`
- `SurfaceMetadata`
- `CellChannel`

A surface remains dense, rectangular, grid-first, and composed of visual cells plus one semantic role channel per cell.

### Scope vocabulary

- `ScopeSpec`
- `CoordinateSpace`
- `RoleSpace`

`ScopeSpec` is the current canonical generalized scope vocabulary. It remains deliberately small: `All`, `Role`, `Rect`, `RowRange`, and `ColumnRange`.

Coordinate and role spaces remain **operation-level context**, not fields inside `ScopeSpec`, for D3. That keeps one reusable scope value from baking in one execution context. Future descriptor work should declare the operation's coordinate and role-space defaults or overrides alongside the scope it references.

Current defaults stay locked:

- geometry scopes default to `CoordinateSpace::DestinationLocal`
- role scopes default to `RoleSpace::SampledSource`

### Write vocabulary

- `CellWrite`
- `CellWritePolicy`
- `RoleWritePolicy`

Pipeline execution and scene composition reuse this same write vocabulary.

The shared rule remains:

```text
SkipTransparentEmpty skips and preserves current destination cell + role.
WriteCell writes the cell exactly, including empty transparent cells.
```

Role writes remain explicit:

- preserve destination role
- copy sampled-source role
- set an explicit role

### Sampler vocabulary

- `CoordinateSampler`
- `PipelineSampler`
- `ShiftSampler`

`CoordinateSampler` is the behavioral sampler contract. `ShiftSampler` is stable proof vocabulary for non-identity sampled-source semantics.

`PipelineSampler` remains a checked schema root for the Phase C proof pipeline. Its name is intentionally pipeline-shaped. A later descriptor phase may rename or wrap sampler declarations for generalized descriptors, but it should preserve the same sampled-source semantics.

### Diagnostics vocabulary

- `SurfaceDiagnostic`
- `SurfaceDiagnosticCode`
- `DiagnosticLevel`

Diagnostics use stable codes plus optional path strings. D3 keeps path strings as the current convention and defers structured fields such as `elementId` or `stageName` until descriptor/recipe schemas create the surrounding identity model.

Current path conventions:

- pipeline stage diagnostics use `pipeline.stage[index].name`
- scene element diagnostics use `scene.element[index].id`

### Scene and element vocabulary

- `Scene`
- `SceneElement`
- `SceneOutcome`
- `ElementId`
- `LayerId`
- `ElementPlacement`
- `ClipPolicy`

Scene composition stays minimal: element identity, optional layer grouping, signed placement, z/declaration order, clipping policy, and the shared cell/role write policies.

### Outcome vocabulary

- `ApplyOutcome`
- `PipelineOutcome`
- `SceneOutcome`

Outcomes are public result vocabulary. They report final surfaces, counts, and diagnostics. They are not a runtime event system.

### Descriptor vocabulary

- `EffectDescriptor`
- `EffectId`
- `EffectDomain`
- `CellAccess`
- `ScopeSupport`
- `ScopeKind`
- `WriteSupport`
- `RoleWritePolicyKind`
- `EffectLifecycle`
- `EffectCompletion`
- `DescriptorValidationError`
- `ValueKind`
- `Value`
- `ValueSpec`
- `NumericRange`
- `EffectInputId`
- `EffectInputSpec`
- `RuntimeMutability`
- `SourceId`
- `SourceDescriptor`
- `SourceKind`
- `SourceInputId`
- `SourceInputSpec`
- `SourceSpec`
- `SourceOutputSpec`
- `SourceOutputSize`
- `SourceRolePolicy`
- `SourceLifecycle`
- `AssetId`
- `AssetKind`
- `AssetFormat`
- `AssetLocator`
- `AssetSpec`
- `AssetRequirement`
- `AssetRef`

Phase E1 makes `EffectDescriptor` a stable contract root. It describes effect identity, broad domain, cell-channel access, supported scopes, supported write policies, and lifecycle category. Phase F1 adds a descriptor-local `inputs` map whose entries declare typed values, defaults, ranges, enum domains, small human-facing metadata, bindability as a boolean capability hint, and runtime mutability. F2 describes `ValueSource`, public parameters, host signals, and bindable parameter-target bindings declaratively. G1 describes `GraphSpec` and `NodeSpec`: a canonical post-compilation graph shape with `NodeId`, descriptor references, `ValueSource` node inputs, F2 bindings, and deterministic order. It still deliberately does not describe runtime execution, direct node/effect-input bindings, source authoring recipe aliases, studio controls, runtime stores, runtime override precedence execution, or real effect ports; those remain later phases. H0 adds `SourceDescriptor` and `SourceSpec` as stable source/asset vocabulary for things that produce an initial semantic `Surface`; this is not canonical recipe syntax and it does not adopt legacy recipe field names.

## Proof implementation and proof-only public artifacts

These names exist to prove semantics, not to define the future descriptor or recipe implementation shape.

### Engine proof harness

- `SurfaceEngine`
- `fnc_apply_from_source_with_sampler::apply_from_source_with_sampler`
- `fnc_scope_coordinate::scope_coordinate`

These are execution helpers. Future schemas should not expose their function shapes.

### Pipeline proof harness

- `SurfacePipeline`
- `PipelineStage`
- `PipelineOutcome`
- diagnostic annotation helpers

`SurfacePipeline` is a public checked schema root **for the current clean-room proof pipeline**. It is not the final runtime graph, phase graph, node graph, recipe compiler, or descriptor registry.

`PipelineStage` is a toy proof enum. Its variants prove ordering, sampling, visual-preserve-role behavior, explicit role writes, and scoped glyph rewrite behavior. Future descriptor work must not treat `PipelineStage` as the effect descriptor model.

### Effect proof artifacts

- `DimEffect`
- `ExplicitRoleWriteEffect`

These are small proof artifacts. The old tiny proof `EffectDescriptor` was retired in Phase E1; durable descriptor vocabulary now lives in `tui-vfx-contract`.

### Evaluation plumbing

- `ScopeEvalInput`
- `IdentitySampler`

These are public from `tui-vfx-contract` because `ScopeSpec::matches` uses them to keep scope semantics self-contained. They are evaluation plumbing, not separate schema roots, and future descriptors should not expose their internal evaluation shape unless a later phase promotes it intentionally.

## Test-only scaffolding

Test helpers in `crates/tui-vfx-contract/tests/*` and `crates/tui-vfx-next/tests/*` are not contract vocabulary. They may create cells, surfaces, scene elements, and schemas to prove behavior, but they must not be referenced by future public docs as implementation APIs.

## Decisions locked by D3

```text
SurfacePipeline:
    checked proof-pipeline schema root, not final runtime graph

PipelineStage:
    toy proof enum, not future effect descriptor model

ScopeSpec:
    canonical generalized scope vocabulary for now

CoordinateSpace / RoleSpace:
    operation-level defaults/overrides, not fields inside ScopeSpec

Pipeline and scene write behavior:
    reuse CellWritePolicy and RoleWritePolicy

Diagnostics:
    keep stable codes and path strings now; defer structured identity fields

EffectDescriptor:
    capability contract plus typed F1 input declarations, G4 output declarations, F2 declarative source/binding vocabulary, and G1 graph/node validation; runtime execution deferred

Graph-local value bus:
    stable G4 contract vocabulary for node outputs, graph value ids, typed kind/shape, graph value sources, and parallel value merge policy; proof execution only

Source / asset contracts:
    stable H0 contract vocabulary for surface-producing sources, source instances, source inputs, asset requirements, structural asset refs, and source output role/size semantics; no recipe compiler or runtime asset/procedural execution

Crate shape:
    tui-vfx-contract owns stable contract DTOs
    tui-vfx-next owns proof execution and depends on tui-vfx-contract
```

## Logical modules in code

`crates/tui-vfx-next/src/lib.rs` keeps three grouping modules after the E0 split:

- `contract` — re-exports stable v3.1 vocabulary from `tui-vfx-contract`
- `proof` — clean-room proof harness and toy implementation exports
- `schema_roots` — proof-pipeline schema root exports

`tui-vfx-contract` is now the direct import home for stable DTOs. `tui-vfx-next` re-exports contract vocabulary for compatibility and proof tests.

## Non-goals

D3 deliberately does not implement:

- value-source descriptor expansion beyond F1 typed input declarations
- recipe schema/compiler
- source authoring schemas
- template expansion
- runtime bindings
- phase graph
- trigger engine
- studio manifest
- legacy migration
- real effect ports
- full layer graph
- complex blend modes

## Handoff to Phase E

Phase E1 started the effect descriptor model with this boundary in place. Phase F1 landed typed input declarations on that descriptor model. Phase F2 added declarative source/binding vocabulary, and Phase G1 added a canonical graph container that validates descriptors, nodes, inputs, parameters, signals, bindings, scopes, write policies, and order together. Future descriptors should extend the contract vocabulary above and must not inherit toy pipeline stage shapes. G2/G3/G4 graph execution is proof-only. H0 source/asset contracts are DTO and validation vocabulary only; runtime source stores, F2 binding execution, direct node/effect-input binding targets, canonical recipe compilers, source-local pipeline syntax, real asset loading, real procedural rendering, real effect/source ports, and override execution remain deferred beyond H0.
