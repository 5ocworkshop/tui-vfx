# Packet 1.2.B — Generalize five `*Pool` types into `Pool<T>`

> **For the assignee.** This packet is the action contract for buy-once sweep
> finding 1.2.B. The investigation behind this scope is in
> `docs/design/tui-vfx-buy-once-architecture-sweep.md` §1.2.B and §6.3 — you
> do not need to re-derive it.

## 1. Task

Define a single generic `Pool<T>` carrying the canonical
`{ items: Vec<T>, policy: PoolPolicy }` shape and the canonical
`new` / `pick` / `is_empty` API. Collapse `ImagePool`, `FontPool`,
`EffectPool`, `PresetPool` to type aliases over `Pool<T>`. Keep `TextPool` as
a thin newtype wrapper because it has a behavioral difference (constructor
sanitization) that does not generalize. Move the four hand-rolled pool
files to `recyclebin/`.

## 2. Why this matters

Five sibling instances of an identical pattern, three of them already
`Pool<String>` in everything but name. Per the sweep §6.3:

- Five-way duplication crosses Intention 23's rule-of-three threshold
  comfortably.
- Smallest blast radius of any L-or-larger consolidation in the sweep —
  `.pick()` has zero call sites outside the pool files themselves and their
  inline tests (verified by `grep -rn "\.pick()" crates/ src/` across
  tui-vfx and tui-vfx-recipes during sweep grounding).
- Adding a sixth pool type (a future `ColorPool`, `ScopePool`, etc.) re-pays
  ~100–280 lines of identical scaffolding per pool. After this packet, a new
  pool is one line: `pub type ColorPool = Pool<Color>;`.

## 3. Success condition

- `Pool<T>` defined in
  `crates/tui-vfx-content/src/pool/cls_pool.rs` with the four-method API:
  `new(items, policy) -> Self`, `pick(&self) -> Option<&T>`,
  `is_empty(&self) -> bool`, `Default`.
- `Pool<T>` derives `Clone, Debug, PartialEq, Serialize, Deserialize,
  ConfigSchema` where the type bounds permit; `Eq` only when `T: Eq`.
- Type aliases land for `ImagePool`, `FontPool`, `EffectPool`, `PresetPool`.
  Each alias carries a domain-specific rustdoc block (the *what is special
  about this T* per sweep §6.3 Option C). Phase 2 extension comments and
  use-case rustdoc on the original files migrate to the alias docstrings.
- `TextPool` is a thin newtype wrapper: `pub struct TextPool(Pool<String>)`,
  with `new(items, policy)` running the existing `sanitize()` pass before
  delegating, plus delegated `pick` / `is_empty` and a `Deref<Target =
  Pool<String>>` for read-only access. The public `pick` keeps its current
  return shape (`Option<&str>`).
- Four hand-rolled pool files (`cls_image_pool.rs`, `cls_font_pool.rs`,
  `cls_effect_pool.rs`, `cls_preset_pool.rs`) moved to
  `recyclebin/crates/tui-vfx-content/src/pool/` per the recycle-bin protocol.
- `Preset` (the *item* type, line 32 of the old `cls_preset_pool.rs`) and
  its `with_*` constructors are NOT deleted — they migrate to a new file
  `cls_preset.rs` in the same directory. The pool wrapper around `Preset`
  becomes the alias `pub type PresetPool = Pool<Preset>;`.
- `crates/tui-vfx-content/src/pool/mod.rs` re-exports the new shape: `pub
  use cls_pool::Pool;`, `pub use cls_preset::Preset;`, the four aliases,
  `pub use cls_text_pool::TextPool;`.
- Workspace `cargo test -p tui-vfx-content --lib --tests --doc` is green.
- Downstream consumers (`tui-vfx-recipes`, `gt-design`) compile unchanged
  because the alias names are import-compatible. If a downstream caller
  consumed `pick() -> Option<&str>` and `Pool<String>::pick` returns
  `Option<&String>`, fix the call site OR add a `pick_str` inherent helper
  on `Pool<String>` — make the call at slice time and document the choice
  in the report. (Sweep grounding showed zero such call sites; if you find
  any, the report must list them.)

## 6. Write scope (smallest justified set)

### Created files

1. `crates/tui-vfx-content/src/pool/cls_pool.rs`
   - Define `pub struct Pool<T> { pub items: Vec<T>, pub policy: PoolPolicy
     }`.
   - Methods: `new(items: Vec<T>, policy: PoolPolicy) -> Self`,
     `pick(&self) -> Option<&T>`, `is_empty(&self) -> bool`. Use the
     existing `pick_index` helper from
     `super::fnc_pick_index::pick_index`.
   - Derives: `Clone, Debug, Default, PartialEq, Serialize, Deserialize,
     tui_vfx_core::ConfigSchema`. Add `Eq` via `#[derive]` only if you can
     bound `T: Eq` in a separate impl; if the derive macro complains, use a
     manual impl gated on `T: Eq`. Keep PartialEq always-on.
   - Inline tests: empty pool returns None, `FirstOnly` picks first,
     `Random` picks one of the items, serde round-trip.
   - Full OFPF metadata envelope (FILE / VERS / WCTX / CLOG header +
     footer).

2. `crates/tui-vfx-content/src/pool/cls_preset.rs`
   - Move `pub struct Preset { ... }` (lines 32–62 of old preset pool) and
     all its `with_*` constructors (lines 64–101) into this file
     verbatim, preserving rustdoc.
   - Full OFPF metadata envelope.

### Modified files

3. `crates/tui-vfx-content/src/pool/cls_text_pool.rs`
   - Rewrite as a thin newtype: `pub struct TextPool(Pool<String>)` with
     `new(items, policy)` calling `sanitize` then delegating, `pick(&self)
     -> Option<&str>` and `is_empty(&self) -> bool` delegated, `Default`
     impl, `Deref<Target = Pool<String>>` for read-only field access.
   - Keep the `sanitize` private helper.
   - Preserve all existing rustdoc and test cases.
   - Bump `<VERS>` and update `<CLOG>`.

4. `crates/tui-vfx-content/src/pool/mod.rs`
   - Replace per-pool `mod` declarations and re-exports with:
     - `mod cls_pool; pub use cls_pool::Pool;`
     - `mod cls_preset; pub use cls_preset::Preset;`
     - `mod cls_text_pool; pub use cls_text_pool::TextPool;`
     - `pub type ImagePool = Pool<String>;` (with rustdoc — see step 5).
     - `pub type FontPool = Pool<String>;` (with rustdoc).
     - `pub type EffectPool = Pool<crate::types::ContentEffect>;` (with
       rustdoc).
     - `pub type PresetPool = Pool<Preset>;` (with rustdoc).
   - Keep existing `pub use col_pool_policy::PoolPolicy;` and other
     non-pool exports unchanged.
   - Bump `<VERS>` and update `<CLOG>`.

### Out of scope

- Do NOT change `cls_text_pool.rs` to be an alias. Its `sanitize` is
  behavioral, not docstring (sweep §6.3 critical sub-rule).
- Do NOT touch `col_pool_policy.rs` or `fnc_pick_index.rs`.
- Do NOT introduce a `PoolExt` trait or `pick_str` helper unless verification
  proves a downstream caller needs it. The sweep grounding said no such
  caller exists; verify and confirm before adding.
- Do NOT bundle Finding 1.2.C (FontRegistry / AssetRegistry consolidation)
  into this packet. That is a separate decision pending the V3 scene-layer
  session.
- Do NOT rename `Preset` to `PoolPreset` or similar. The existing name is
  the public surface.
