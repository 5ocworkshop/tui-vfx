# Packet 1.3.A — Lift `VfxImageSource.image_name` to `BindableString`

> **For the assignee.** This packet is the action contract for buy-once sweep
> finding 1.3.A. Read it top-to-bottom before touching code. The investigation
> behind this scope is in
> `docs/design/tui-vfx-buy-once-architecture-sweep.md` §1.3.A and §6 — you do
> not need to re-derive it.

## 1. Task

Change `VfxImageSource.image_name` from `String` to
`tui_vfx_style::BindableString`, and lower every `Binding(...)` arm to
`Literal(...)` at the V3 compile bridge so the scene runtime continues to
consume a literal string. Add one `_bindable` debug recipe that exercises the
binding form end-to-end through the compile path.

## 2. Why this matters

Today recipes that want a runtime-bound logo name have no schema surface for
it. The cycle plan v0.7.0 line 22 calls this out as **"independently
actionable"** — independent of the L2 binding-loopback work (already shipped)
and independent of the deferred Phase 7.bytes resolver consolidation. The
change satisfies three constraints in one cutover:

- Phase 6 set the precedent (`MechanicalContentSource::Preset.font:
  Option<BindableString>`); Phase 7.schema completes the symmetric pair on the
  scene side.
- Intention 38 (`_bindable` filename + tag convention) needs an exemplar that
  isn't a font — image is the second canonical case.
- The "no parse-and-inert" feedback rule (`feedback_no_inert_schema.md`)
  forces the schema lift and the runtime wiring to land in the same commit.

## 3. Success condition

- `VfxImageSource.image_name: BindableString` in
  `/usr/projects/tui-vfx-recipes/src/recipe_schema/scene/cls_ra_image_source.rs`.
- Recipe authors can write any of:
  - `"image_name": "splash_logo"` (bare literal, lenient)
  - `"image_name": {"literal": "splash_logo"}` (tagged literal)
  - `"image_name": {"binding": "selected_logo"}` (binding into
    `requires_bindings`)
- The binding form lowers to a literal at the V3 compile bridge, using the
  same `binding_defaults` + `overrides.runtime_params` lookup chain that
  `resolve_layer_visibility` (line 260 of
  `fnc_build_scene_source_from_compiled_plan.rs`) already uses for layer
  visibility predicates.
- One new debug recipe exercises the binding form and round-trips through the
  compile + scene-render path.
- All existing tests in `tui-vfx-recipes` continue to pass; new packet-level
  tests cover (a) lenient bare-string serde, (b) tagged-literal serde, (c)
  tagged-binding serde, (d) compile-bridge resolves binding to literal using
  loopback, (e) compile-bridge prefers `runtime_params` override over
  loopback.

## 4. Mode

`FAMILY_MODE` — touches schema (recipes), compile bridge (recipes), scene
runtime (recipes), and one debug recipe (`tui-vfx-recipes/recipes/`). No
edits in `tui-vfx` workspace. No edits in `gt-design` or `mixed-signals`.

## 6. Write scope (smallest justified set)

### `tui-vfx-recipes` (the only repo edited)

1. `src/recipe_schema/scene/cls_ra_image_source.rs`
   - Change `pub image_name: String` to `pub image_name:
     tui_vfx_style::BindableString`.
   - Update `Default::default` accordingly
     (`BindableString::Literal(String::new())`).
   - Bump `<VERS>` and update `<CLOG>`.

2. `src/v3/compile/fnc_build_scene_source_from_compiled_plan.rs`
   - Extend `resolve_source_tokens` (or add a sibling
     `resolve_image_source_bindings` helper called from the same site) so the
     `RaContentSource::Image` arm walks `image_name`: if it is `Binding(key)`,
     resolve via `overrides.runtime_params.get(key)` first, then
     `binding_defaults.get(key)` (loopback), and replace with
     `BindableString::Literal(...)`. If neither resolves, return a
     `BuildCompositionSpecError` (this should be unreachable post-validate,
     but the explicit error documents the invariant). The `resolve_source_tokens`
     signature today takes only `&HashMap<String, String>`; you will need to
     add `binding_defaults` and `runtime_params` (or wrap them) — match the
     call style of `resolve_layer_visibility` at line 260.
   - The bridge call site (`bridge_scene_layer`, line ~218) must thread
     `binding_defaults` and `overrides` into the new helper just as it
     already does for `resolve_layer_visibility`.

3. `src/scene/layers/cls_image_layer.rs`
   - One-line change at line 28: `&source.image_name` becomes
     `source.image_name.literal().expect("compile bridge guarantees Literal")`,
     OR safer: `source.image_name.literal().unwrap_or("")` with an
     explanatory comment. Choose `expect` to encode the invariant, since
     reaching the runtime with a `Binding` arm is a compile-bridge bug, not a
     fallback case.
   - Same pattern at line 68 (the fallback-reason format string).

4. `src/scene/orc_compose_scene.rs` line 235
   - `name: source.image_name.clone()` becomes
     `name: source.image_name.literal().unwrap_or("").to_string()` or
     equivalent. (This is in the `AssetResolved` trace event — a missing
     literal here should not fail rendering; an empty string is acceptable
     trace data.)

5. `recipes/debug_recipes/content/content_image_bindable.json` (or the
   nearest existing scene-image debug recipe location — confirm by
   listing `recipes/debug_recipes/scene/` if that path exists)
   - New recipe demonstrating the `binding` form. Filename ends in
     `_bindable`; `metadata.aesthetic_tags` includes `"bindable"`. Use the
     existing odometer recipe as the template for the metadata block. Declare
     a `requires_bindings` entry for the binding key with a
     non-empty literal loopback so the validate gate (Intention 37) passes.
     Provide a clear authoring_notes block explaining the binding form.

## 12. Closing reminder

This is a **schema lift with compile-bridge resolution**, not a runtime
re-architecture. The runtime stays oblivious to the `Binding` arm; the
compile bridge guarantees a `Literal` reaches the scene. If the helper
function in step 6.2 cannot satisfy that guarantee for any path, surface that
finding instead of inventing a runtime fallback — the no-parse-and-inert
rule means the *schema lift waits* until the wiring is complete.
